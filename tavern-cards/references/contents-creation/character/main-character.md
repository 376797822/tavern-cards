# 主角级角色模板

用于编写可被 {{user}} 代入的主角色。每个主角一条独立条目，**不拆分**为多个条目（基础信息 + 性格调色盘 + 三面性等），全部整合在一条条目中。

## 约束

- 只有可被 {{user}} 代入的角色才使用此模板
- 条目使用 `<World_MainChar_$Name>` XML 标签，`$Name` 替换为角色名
- 此模板整合了基础信息、性格、NSFW 信息，不再拆分条目
- 身份字段按场合拆分，遵循世界书中的身份感知系统

## 模板结构

```

  此为可选主角之一。{{user}}若代入${该角色姓名}，则以下为{{user}}的身份。

  初始信息:
    姓名: ${该角色姓名}
    年龄: ${年龄}
    性别: ${性别}
    身份: ${按场合拆分的不同身份}
    样貌: ${简要样貌介绍}

    社交情况: ${社交圈子，日常接触人群，与谁相识、与谁交好或交恶等}

  性格信息:
    待人接物倾向: ${与他人互动时的思维方式、行为准则、认知状态}
```

## 字段说明

### 初始信息

| 字段 | 说明 |
|------|------|
| 姓名 | 角色姓名，如有本名/化名一并列出 |
| 年龄 | 年龄 |
| 性别 | 性别 |
| 身份 | **按场合拆分**——同一角色在不同场景下身份不同。如：冒充少爷时是体面后生，独处时是逃奴，面对知情人时是共谋者 |
| 样貌 | 简要样貌介绍，遵循"外貌只写特征"原则，遮住名字能认出是谁 |
| 体格 | 体态特征、力量感、健康状况、显著的身体特征（如老茧、疤痕等） |
| 社交情况 | 社交范围、日常接触人群、与谁相识、与谁交好或交恶。决定角色在城中能接触到什么人、有什么信息渠道 |

### 出身

角色来历和关键事件。只写对角色产生了实际影响的事，不要流水账。每条独立成行。

### 现状

当前处境。分条说明，覆盖角色的主要困境和机会。

### 社交关系

内部按方向划分，每条写具体画面而非抽象评价：

| 方向 | 说明 |
|------|------|
| 与家人/亲属的关系 | 与家人、亲属的关系，具体画面，谁亲谁疏 |
| 与朋友/同侪的关系 | 与朋友、同事、同侪的关系，谁可信任、谁有龃龉 |
| 与重要对手/敌人的关系 | 与对手、敌人、宿怨的关系及历史 |
| 与 {{user}} 的关系 | 与 {{user}} 的关系定位、认识过程、互动方式等 |

### 目标

- **长期目标**：角色最终想达成的状态，驱动角色长期行动。写 1-3 条，每条方向各不相同（避免同义反复），如事业/复仇/守护不同领域各一条
- **短期目标**：当前最紧迫要做的事，是角色近期的行动指南。写 1-3 条，每条方向各不相同

### 本领

角色拥有的技能和水平。包括优势技能和明显短板。

### 性格信息

五项倾向，覆盖角色在五个维度上的思维方式、行为准则和认知状态：

| 倾向 | 说明 |
|------|------|
| 待人接物倾向 | 与他人互动时的模式——观察方式、回应方式、信任建立方式 |
| 突发处理倾向 | 面对意外、危机、突发状况时的第一反应模式 |
| 对待善恶倾向 | 对善事和恶事的判断标准、做出善恶行为时的心理状态 |
| 对待强弱倾向 | 面对强者和弱者时的态度差异——服从、反抗、同情、利用等 |
| 自我推进倾向 | 没有明确目标时，或完成上一目标后的行为模式——是闲下来还是继续找事做 |

**约束**：每个倾向写具体的行为模式和认知状态，不写抽象标签。示例——"对待强者本能的反应是服从与讨好，对待弱者的本能是同情与提防"，而不是"性格软弱"。

### NSFW 信息

| 字段 | 说明 |
|------|------|
| 尺寸 | 详细数值或类比：勃起前后长度/周长/粗细等，如"常态约 9cm，勃起后约 16cm，周长约 13cm"，或类比常见参照物 |
| 形态 | 用类比或数值描述龟头、冠状沟、包皮、柱身弯曲度、表面纹理等特征 |
| 睾丸 | 用类比或数值描述睾丸大小/形态/位置、左右是否对称等 |
| 特征 | 特殊标记如伤痕、弧度、肤色差异等，可用类比描述 |
| 性能 | 性能力、耐久、勃起反应、射精量、恢复速度等，可含数值 |
| 性知识了解程度 | 对性知识的了解程度、来源（书本/实践/听闻）、是否有实践经验 |
| 历史 | 过往性经历 |
| 倾向 | 性倾向、偏好 |
| 习惯 | 性方面的习惯行为 |
| 认知 | 对性和两性关系的认知与态度 |
| 爱好 | 在性方面的具体爱好 |

### 注释信息

其他需要注意的信息，如角色隐藏的秘密、与其他角色的特殊关系等。

## 编写顺序

- 主角模板在创作规划中列为 `entries` 中的一条，类型为 `角色`，part 为 `main`
- 编写时直接产出完整的主角色条目，不再拆分基础信息、性格调色盘、三面性等
- 编写完成后在 entryManifest 中注册为 `角色/{角色名}_主角`，使用 `<World_MainChar_$Name>` 标签
